# 快照的可信度必须显式声明，缺省即错误

铸造快照时可信度是必填输入：协议声明写一次（通常是 `official`），代码适配器在每个返回路径写明。

背景：`src/main/adapters/types.ts` 的 `snap()` 曾把 `dataQuality` 默认成 `official`、`dataAt` 默认成 `ctx.now` —— 于是「什么都不说」就自动获得最可信的标签。Claude 与 Codex 的百分比来自本机转录加上社区预设限额（它们自己的 `detail` 文案里就写着「估算」），却因此被标成 `official`；`collectAll` 兜底的错误快照根本没有这个字段，下游把它读成 `official`。这与 DESIGN.md §3.2 的诚实原则正好相反 —— 那套策略在 `src/shared/quality.ts` 里被 32 条断言覆盖着，却只能管显示，看不见盖错的章。

决定：反转默认值。缺少可信度是编译错误，而不是一个谎言；「本机估算」不可能因为遗漏而被展示成官方数据。同一次铸造也使用数据源自己的时间戳（当它提供时），不再一律 `now`。

## Consequences

这条容易被后人「顺手简化」回去 —— 给 `provenance` 加个默认值能少写很多行。不要加：漏一次就是一个误导用户的数字。
