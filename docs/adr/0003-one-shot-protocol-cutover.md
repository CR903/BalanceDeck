# 供应商协议重构采用一次性切换，先以黄金样本冻结旧行为

跨越全部供应商适配器的这次重构一次性切到底，而不是逐个迁移；切换前先把旧行为冻结成「黄金样本」测试。

背景：决策时仓库是 v0.1.1、8 次提交、没有外部用户。当时没有任何适配器测试 —— `src/main/adapters/types.ts` 经 `types.ts:2 → net.ts → electron` 无法被 `scripts/lib/load-ts.mjs` 加载（报 `Dynamic require of "fs" is not supported`），唯一兜底是 `--uitest`（需要 GUI、联网与 macOS 托盘）。另外两份测试是内联副本且已经漂移：`scripts/test-ssr-parser.mjs:22` 只认整数百分比，而 `src/main/adapters/opencode-cookie.ts:124` 已改为接受小数。

决定：引擎、协议声明与协议目录合并一次做完；8 个 keyed 适配器的旧行为先冻结为黄金样本（状态 / 窗口 / 可信度 / 提示语），等价性用「旧适配器输出 == 新引擎输出」机械验证，不靠人工比对或 `--uitest`；8 个旧文件随切换一起删除。

理由：项目太年轻（0.x、无外部用户），双轨并存的成本高于切换窗口内中间态不可用的成本。

## Considered Options

- **渐进迁移**（评审推荐）：先把 8 个 keyed 适配器改成走声明、逐个删旧文件。安全，但要在很长一段时间里同时维护两套实现与两套夹具。
- **先共用 wire helper，声明化往后放**：先把 4 处 GET + 超时合并、让 7 个代码适配器接上。在没有回归网的情况下先动 7 个文件，且重复的解析逻辑与内联副本仍然存在。

## Consequences

这是流程约定，不是架构不变量：等仓库有了稳定的适配器回归网（`npm test` 能覆盖适配器），可以回到渐进迁移，本文不构成约束。
