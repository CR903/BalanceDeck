# daily → knowledge 沉淀门禁（P2）

> `AGENTS.md` 引用的「P2 沉淀门禁（trellis-check 必检）」的可执行定义。
> 在 `task.py archive` / `/trellis:finish-work` 之前，**check 阶段**照本文件自检。

## 为什么要有这道门

日志（`docs/daily/`）回答「这次做了什么」，知识（`docs/knowledge/`）回答「下次不该再踩」。
不设门禁的后果是**日志越来越厚、知识永远是空的** —— 同一个坑换个任务再踩一次，因为当初只把它
记成了一次性事件，没人把它写成准则。本门禁只拦一件事：**日志里已经出现了可复用结论，但
knowledge 没跟上。**

## 3 问（逐条回答，答「是」就必须沉淀）

1. **换一个任务还会再遇到吗？** —— 只发生一次的交付细节（某个端点的字段名、某张截图的尺寸）
   不是知识；会再次遇到的结构性问题（缓存键怎么取、闸门能不能跨 `await`、护栏怎么才有牙）才是。
2. **能写成「遇到 X → 做 Y，否则 Z」吗？** —— 写不出这个形状的是感想。写成「否则 Z」这一半
   才算把代价说清（否则读者不知道不做会怎样）。
3. **有取证吗？** —— 命令 / 数字 / 文件行号至少一样。没有取证的结论下一轮就会被反驳，
   而**被反驳一次的准则比没有准则更糟**（它会让后来者不再信任这一层）。

## PR Checklist

- [ ] `docs/daily/YYYY-MM-DD_<slug>.md` 已写（照 [`template.md`](../../template.md)），含「取证（命令 + 原始输出）」与「未完成 / 存疑」两节
- [ ] `docs/index.md` 对应年月表格**已追加一行**（日期 / 日志链接 / 任务 slug）
- [ ] 3 问已逐条回答；有「是」的项 → 知识已落到 `docs/knowledge/<端>/<分类>.md`
- [ ] 该端 `index.md`（如 [`main/index.md`](../main/index.md)）**已加行**：一句话写清「遇到 X → 做 Y，否则 Z」
- [ ] 总 [`docs/knowledge/index.md`](../index.md) 的端目录表**已加行**（新端/新分类时才需要）
- [ ] 新知识里引用的**文件行号 / 数字 / 命令**是当轮实测的，不是从旧文档抄的

## 拦截规则

**日志含坑位或通用解法，但 `docs/knowledge/<端>/<分类>.md` 与两级 `index.md` 未更新 → 拦截 archive。**

判定方式（人工核对，别指望脚本猜语义）：

```bash
# ① 这篇日志有没有出现「坑/教训/以后注意/否则」这类段落
grep -nE "坑|教训|以后注意|否则" docs/daily/2026-XX-XX_<slug>.md

# ② 命中①时，knowledge 与两级索引有没有对应的新增行
git diff --stat docs/knowledge/
grep -n "<关键词>" docs/knowledge/*/index.md docs/knowledge/index.md
```

②为空而①非空 = 拦截。

## 什么不算知识（别硬塞）

- **一次性事实**：某个端点的字段名、某张参考图的尺寸、某次发布的时间。
- **复述实现**：把 `design.md` 的取舍抄一遍 —— 取舍属于任务产物，不属于跨任务准则。
- **没有代价的偏好**：写不出「否则 Z」的，先留在 daily，等它在第二个任务里再次出现时再沉淀。
- **过期后必须删**：知识一旦被实现改动作废，同轮就要改或删；留一条错的准则比留空更危险。
