# 球形态：去掉浅色皮肤下的背景框 + 5H 移到数字下方 + 自动轮播先走完窗口

> 任务 `09-28-dot-frame-label-carousel`，P1。上一任务 `09-27-dot-ring-scroll` 的用户实测反馈。

## 一、需求

### R1 球不得借用页面级表面令牌（背景框）

`.petball-fallback` 用 `background: var(--bg)` 当底盘。`--bg` 是**主界面卡片/页面的表面色**，
与「桌面壁纸长什么样」毫无关系，于是球的外观被皮肤绑架。

**实拍取证**（`BD_SKINS=1 npx electron . --ballshot`，`/tmp/balancedeck-shots/ball-skin-*.png`）：

| 皮肤 | `--bg` | 球盘实测 |
|---|---|---|
| `aero`（浅色） | `rgba(246,246,248,0.72)` | 浅灰盘 |
| `minimal` 极简白 | `#ffffff` | **纯白盘** |
| `candy` 渐变彩 | 粉蓝渐变 | 浅色盘 |
| `ink` 墨纸 | `#f4f1ea` | **米色盘**（白底桌面上非常明显） |
| `dark` 深色科技 | `#101014` | 黑盘 ✓ |

6 个皮肤变体里 **4 个给浅色盘**。而 `dark` 之所以「看起来没问题」纯粹因为它碰巧和深球同色 ——
不是设计，是巧合。

**关键取证（推翻了「球应当恒定」的直觉）**：`--track` 是**逐皮肤对着该皮肤的球盘调**的 ——
`minimal` 用 `rgba(0,0,0,0.08)`（深色轨道，配浅盘），`dark` 用 `rgba(235,235,245,0.14)`
（浅色轨道，配深盘）。**球的底色跟随皮肤是现有令牌体系的自洽设计**，不是缺陷；
`--track`/`--dot-rim`/`--dot-bottom` 三个令牌 5 个皮肤全都定义了，唯独**缺一个表面色**，
球才去借了页面级的 `--bg`。

**要求（2026-09-28 用户拍板：逐皮肤补球表面令牌）**：新增球专属的表面令牌（如 `--ball-bg`），
逐皮肤取值，**不再借 `--bg`**；`minimal`/`ink` 这类浅盘要把 rim/track 的对比加强，
让球在白底桌面上读作「一个物体」而不是「一块底色」。尊重皮肤作者的配色意图，
**不改「球随皮肤变色」这件事本身**。外部皮肤（`ext:*`）未定义时要有兜底，不许塌成透明球。

### R2 去掉 `backdrop-filter`（**保留，但病根另有其人 —— 2026-09-28 实机复测后订正**）

`.petball-fallback` 曾写着 `backdrop-filter: blur(24px) saturate(180%)`，注释意图是「磨砂桌面背景」。
但**悬浮窗是 `transparent: true`（`src/main/overlay.ts:138`），页面内 `html/body/#root` 全部
`background: transparent` —— 页面里不存在任何可被采样的 backdrop**，它履行不了注释宣称的职责。
**这一条删除成立，予以保留。**

⚠️ **但它不是用户报的那个「球外面套一圈浅色方框」的成因** —— 删掉后方框仍在（用户实机复测）。
本条原先把方框归因于此，是**错误诊断**，已订正（见 R5）。

**教训（已订正，2026-09-28 check）**：原文写的是「`capturePage` 拍不到屏幕合成结果，因此
**「实拍没变化」不能当作「改对了」的证据**」。**这句话是错的**，它把两件事混成了一件：
`capturePage` 确实不合成桌面 backdrop（所以它拍不到「球透出壁纸」），但**方框是页面自己画在
窗口内的 alpha，而 capturePage 拍的正是这 56×56 的窗口内容 —— 它拍得到**。逐像素解码实测
（`node scripts/lib/png-probe.mjs`，免 Screen Recording 权限）：修复前 5 个皮肤**一致**地
球外 2688/2688 个像素 alpha>0、alpha>0 的最远半径 78.5px（窗口对角线）= 四角被填成方形；
修复后 208/2688，全部落在球沿 0.7px 内（抗锯齿），离球沿 2px 以外 0 个。

真正的教训因此改成两条：① 症状无法被观测时，先解决观测手段（这条仍成立，`screencapture`
无权限那段是真障碍）；② **观测手段一直都在，失败的是「读」它** —— 112×112 的 PNG 用肉眼看
是一张几乎全透明的图，方框却占满了球外 100% 的像素。要下结论就解码，别用肉眼扫缩略图。

### R5 方框的真正成因：`.petball-fallback` 的 outer box-shadow（2026-09-28 实机定位并修复）

**三次误诊的完整记录见 `design.md` §9**（`backdrop-filter` → 原生窗口层 → 「不透明浅灰底」，
每一次都被自己的证据推翻）。这里只留结论。

**用户两个实机观察**：方框**跟着球移动**（属于我们的窗口）、**颜色不随桌面变化**（不是半透明透出）。

**复现与测量**（前提：Screen Recording 授权 + 纯白全屏窗口打底，因为深色壁纸上该方框只差 6 级、肉眼与阈值都测不到）：

- 方框像素范围 = 屏幕 `x[1200..1255] y[300..355]` = **56×56 pt = 窗口本身**，均色 `rgb(218,218,218)`，圆角 ≈9pt
- CDP 逐项二分（同一会话连抓 5 张）锁定 `.petball-fallback` 的
  **outer `box-shadow: 0 6px 18px rgba(0,0,0,0.28)`**：
  注入 `box-shadow:none` 后窗口顶缘 `y=300` 由 `253,252,252,251,251,250` 变为 **255,255,255,255,255,255**

**机理**：收起态窗口 = 56×56 = 该元素 56×56，**外阴影没有任何容身之处**；但它仍被绘制 ——
一个从 56×56 的圆扩散出去的模糊光晕，被 56×56 的窗口裁切，于是**窗口内、圆外**的那四块
（四个角）留在画面上，浅灰方框就浮在球外，**形状是方的，尽管元素是 `border-radius:50%` 的圆**。
白底上 0.28 黑的模糊衰减正好落在实测的 204–229。
（2026-09-28 check 补记：原文这里写的是「macOS 按方形轮廓合成」。**这一步并不需要** ——
窗口把圆形光晕裁成方形本身就足以解释所看到的全部现象，见下面 capturePage 的 alpha 实测。）

**capturePage 侧的独立证据**（免 Screen Recording 权限，可复现）：
`node scripts/lib/png-probe.mjs <ballshot 出的 png>` —— `capturePage` 拍的**就是这 56×56 的
窗口内容**，而方框是页面自己画的 alpha，所以它拍得到。5 个皮肤实测完全一致：

| | 球外 alpha>0 像素 | alpha>0 的最远半径 | 离球沿 2px 外仍带 alpha |
|---|---|---|---|
| 修复前（`0 6px 18px rgba(0,0,0,0.28)`） | **2688 / 2688 = 100%** | **78.5px**（窗口对角线；球盘半径仅 56px） | 2132 |
| 修复后 | 208 / 2688 = 7.7% | 56.7px（球沿 0.7px 抗锯齿） | **0** |

**要求**：删掉该 outer box-shadow，保留三条 inset（顶部发丝高光 / 盘缘 / 底部内阴影）；
立体感由 inset 提供，**不依赖任何投影**。

**同一机理的第二实例：改名输入框**（2026-09-28 用户拍板一并去掉）。
`.petball-rename input` 的 `0 6px 20px rgba(0,0,0,0.35)` 是**同一个故障**：输入框只有
168×28，但它**活在同一个 56×56 窗口里**，20px 的模糊光晕照样把窗口铺满 —— 实测 112×112
像素 **100% 带 alpha**（12544/12544）。上一轮记为「观感上是输入框有投影、属产品取舍、
未改」，那个判断是错的：**窗口照样把它裁成方形**，白底桌面上右键改名会闪出一块深色方块。
判据不是「这个投影是不是有意画的」，而是「**这个元素的盒子是不是等于或大于窗口**」。

**结构门 D6 因此从「守一个选择器」扩成「守宠物窗口内满幅/溢幅元素这一类」**（见
`design.md` §6.1 与 `implement.md` 批次表）：`.petball.no3d .petball-fallback`、它的
`:active` 按压态、`.petball-rename input`（168×28 > 窗口）、`.petball-hit`
（`inset:0` = 整块窗口）逐个独立判「`box-shadow` 逐层都是 inset」。
（`.petball-debugring` 一度在表里，理由「外接框 = 整个窗口」是**假的** —— 它只可能是人物形态、
球形态压根不渲染，已移出。）

⚠ **展开态那 13 处 outer `box-shadow` 不在本门管辖内，也仍然不该动** —— 但理由不是
「都被 padding/margin 内缩」（**实测不成立**：`.pcard` 的右边框在 384 宽的窗口里只离边
**14px**，`.pcard.dragging` 的 36+30px 阴影确实被窗口边界裁掉了）。真正的保护是
`.card` 自己是 `width/height:100%` + `border-radius:16px` + `overflow:hidden` 且**没有自己的
box-shadow**，把后代的所有墨迹溢出裁进圆角矩形内。实测右缘 alpha 轮廓对称收口
（x=370 → 行 0..600，x=376 → 2..598，x=382 → 8..592），**圆角矩形之外 0 个像素带 alpha**。
潜藏风险因此在 `.card` 而不在那些阴影本身（改掉它的 `overflow` 或把圆角设成 0 就会长出
同样的方框）—— 本任务范围只在宠物窗口，**这条门未加，如实记录**。

**范围外**：`roundedCorners: false` 与创建后 `setBackgroundColor('#00000000')`
曾被试过，实测**对方框无效**（只把圆角从 9pt 变成 6pt），**已全部撤回**。
⚠️ `overlay.ts` 现在与 HEAD 的唯一差异是 `createOverlay` 里 `hasShadow` 上方那段**注释**：
原文把方框归给「macOS 按窗口矩形投的原生阴影」，那是**误诊 #2**，已订正并指向 design.md §9。
`hasShadow: !state.collapsed` 这个**行为本身没动**（「收起态不用原生阴影」的理由仍然成立）。

## 二、验收

### R1 / R2 背景框
- AC1.1 球盘底色由**球自己的令牌**决定：`.petball-fallback` 的**生效声明**里是 `var(--ball-bg)`，
  且不引用 `--bg`。
  ⚠ 判据必须**剥注释后按选择器配平花括号取整块**（2026-09-28 check 修正）：原文写的
  `grep -A14` 够不到 `background`（它在选择器下方第 18 行），且 `grep petball-fallback` 的
  首个命中是 `:root` 里的一条注释 —— 照字面执行会写成一条**永真的假护栏**。
  由 `scripts/test-structure.mjs` 的 D1 执行。
- AC1.2 5 个内置皮肤逐个实拍（`BD_SKINS=1 npx electron . --ballshot`）：`--ball-bg` **5 个皮肤都有定义**，
  且每个值的**对比度**足以让盘与桌面分开（`minimal`/`ink` 重点验）
- AC1.3 `.petball-fallback` 的**生效声明**里没有 `backdrop-filter` / `-webkit-backdrop-filter`。
  ⚠ 判据必须**剥注释**（2026-09-28 check 修正）：该块内有一条注释解释「这里原来有
  backdrop-filter、为什么删」——它是本任务最有价值的一条知识，不能为了让字面 grep 归零而删掉。
  照原文的「块内 grep 0 命中」执行，这条 AC **永远为假**。由 D2 执行。
- AC1.4 **球盘之外没有任何方形 alpha**（AI 侧可自行取证 —— 2026-09-28 check 订正了本条原先的前提）：
  `--ballshot` 的 `capturePage` 拍的**就是 56×56 的窗口内容**，方框是页面自己画在窗口内的
  alpha，所以它**拍得到**。逐像素解码（`node scripts/lib/png-probe.mjs <png>`，免权限）断言：
  球外 alpha>0 的像素占比 ≈ 0，且 alpha>0 的最远半径 ≈ 球盘半径 + 1px 抗锯齿。
  ⚠️ 原先写的「AI 侧拿不到这个证据，必须由用户确认」建立在**一个被证伪的前提**上
  （把「不合成桌面 backdrop」当成了「拍不到方框」）：本机 `screencapture` 无 Screen Recording
  权限那部分是真障碍，但方框根本不需要它。**纯白桌面的肉眼确认仍值得做**（它验的是屏幕合成，
  PNG 验不了），只是不再是「AI 无法取证」
- AC5.1 **宠物窗口内「盒子等于或大于窗口」的元素，其 `box-shadow` 中不存在任何非 inset 阴影**
  （结构门 D6 的 4 条 `no-outer-shadow`：底盘 / 底盘按压态 / 改名输入框 / 命中层；
  判据 = 按**顶层逗号**切层 —— `rgba(0,0,0,0.28)` 里有逗号，裸切会造出假层；剥注释 +
  按选择器配平花括号取整块 + `body != null` 前置，否则选择器一改名就空洞地变绿）
- AC5.1b 底盘**至少保留 1 层** inset（AC5.3 的结构化表达；0 层时「没有非 inset 层」空洞成立）
- AC5.1c 右键改名时窗口内**不再出现深色方块**（`--ballshot` 拍不到改名态，这条是结构门 +
  人工确认；改名框本身是深色 `rgba(20,20,22,0.72)` + 1px 强调色边框，辨认度不依赖投影）
- AC5.2 球在**亮**与**暗**两种底色上都只呈现圆形，四角无任何方形底。
  实测（2026-09-28）：纯白底窗口顶缘 = 255,255,255（与窗口外相等）；
  深色底（30/48 中性灰）y=350 处窗口内 x1200..1210 = 48,48,48，**与窗口外 x1196..1199 逐像素相等**。
  ⚠️ 诚实标注：暗底那侧是 Preview 深色工具栏的**深中性灰**，不是字面意义的 0,0,0 纯黑桌面
  （iTerm 挡住了桌面，无法把球放到纯黑壁纸上看）。与底色无关的兜底证明是 alpha 层面的
  ——球外 7.7%、最远半径 56.7px = 球沿，见 AC1.4。
- AC5.3 球的立体感（顶部高光 / 盘缘 / 底部内阴影）**由 CSS inset 阴影提供**，不依赖任何投影
- AC5.4 **纯白全屏窗口打底 + 实屏抓屏**（`screencapture`，需 Screen Recording 权限）实测：
  窗口内**非球的像素全部为 255,255,255**；与 AC1.4 的 PNG 解码互为独立证据
  （一个验屏幕合成、一个验页面 alpha）
- AC1.5 外部皮肤（`ext:*`）无该令牌定义时**不塌陷**（有 `:root` 兜底），不出现透明球

### R3 标签
- AC3.1 标签渲染在百分比**正下方居中**，多窗口时显示、单窗口仍不显示（沿用上一任务口径）
- AC3.2 **只管标签**：标签不压环（环笔画内缘 r=19.5 以内）、不压数字（紧邻其下、间隙 ≤5px）、不溢出 56×56。
  ⚠ **数字的既有内探不在本任务范围**（2026-09-28 check 裁决）：4 字值（`37.1%`）的数字墨迹
  最大半径 20.6px > 环笔画内缘 19.5px，探入 1.1px。这是 4 字值比 3 字值宽的**既有事实**，
  旧角落布局下余量更小（≈0.3px），轨道与盘面亮度只差 ~20 级、无视觉碰撞；
  数字的字号/字距是上一任务的既有设计，不在本任务改动范围，因此**不为此加 `padding-top`**
  —— 那会把整组推离几何计算值。若将来要收数字内探，另立任务。
- AC3.3 标签字体与 `--dot-value` **不是同一个 stack**（`grep` 可验），且为 8–9px
- AC3.4 标签取值仍来自 `shortWindowLabel()`，随窗口切换同步变化

### R4 自动轮播
- AC4.1 一个有 3 个窗口的供应商：自动轮播**先**依次显示 3 个窗口，**之后**才换供应商
- AC4.2 单窗口供应商：自动轮播直接换人（不空转一步）
- AC4.3 手动操作后仍**暂停 8 秒**，第 9 秒起恢复（沿用上一任务 AC4.3）
- AC4.4 手动左右切供应商后落 `windows[0]`，随后的自动轮播从那里**继续往后**走（不跳回 5H 之外的地方）
- AC4.5 人物形态零影响（上一任务 8 个确定性字段逐位不变）
- AC4.6 充值余额供应商（无环）同样遵守「先走完窗口再换人」

## 三、约束

- 不引入新依赖、不新增设置项、不新增持久化键
- **不新增 WebGL 上下文**（球形态保持 2D）
- 上一任务的四条设计红线继续有效，其中红线「换人唯一入口」需按 R4 微调（见 `design.md`）
- `--uitest` 必须带 `BD_USER_DATA=<临时目录>`；`npx electron . --X` 跑的是 `out/`，
  **任何源码改动后先 `npm run build`**（`quality-guidelines.md` 已有该契约）
- 磁盘仅剩 ~4GB，`--uitest` 偶发挂起是已知退出 flake

## 四、范围外

- 人物形态（`BD_PET=1`）的任何视觉改动
- 轮播节奏（6 秒）与暂停时长（8 秒）的调整
- 外部皮肤作者文档（只保证不塌陷，不为外部皮肤定调色板）
- 主界面卡片里是否也该有同样的表面令牌（另立）
