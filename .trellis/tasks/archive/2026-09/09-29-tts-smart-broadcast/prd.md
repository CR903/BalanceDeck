# TTS 集成与智能播报

## Goal

集成免费 TTS 服务替代系统语音，并实现智能播报触发机制（余额预警+用量波动检测），避免无效播报浪费 TTS 调用次数。

## Background

- 当前播报间隔档位：1/3/5/10/15/30/60 分钟，默认 60 分钟
- 播报逻辑在 `App.tsx` 的 `speakBalance` 函数中
- 使用系统语音 `speechSynthesis`，存在 macOS/Windows 音色差异
- 播报内容：供应商名 + 余额/用量摘要
- 用户提供的免费 TTS 服务：`https://voice.mytts.ccwu.cc/v1/audio/speech`
  - 基于 Microsoft Edge TTS，20+ 中文音色
  - 男声：云希/云扬/云健等；女声：晓晓/晓伊/晓辰等
  - 完全免费，无需 API Key
  - 返回 MP3 音频（实测 1.71s / 11376 bytes / 48kbps 24kHz mono）
  - 旧域名 `tts.chour903.workers.dev` 在国内被 DNS 污染（解析到 Facebook IP 段），**已弃用**

## Requirements

### 功能需求

- **FR1**：集成免费 TTS 服务（`https://tts.chour903.workers.dev/v1/audio/speech`）
- **FR2**：TTS 服务支持配置（默认使用免费服务，支持自定义其他付费服务）
- **FR3**：若未配置 TTS 服务，则不播报（播报必须开启 TTS 服务）
- **FR4**：智能播报触发机制 — 只在以下情况播报：
  - 余额即将用完（阈值可配置）
  - 使用量大幅波动（阈值可配置）
  - 用量即将耗尽
  - 长时间未使用
  - 异常使用模式（阈值可配置）
- **FR5**：播报间隔可调整（默认 1 小时）
- **FR6**：保留系统语音作为回退（当网络 TTS 不可用时，可配置）
- **FR7**：历史数据采集 — 每次刷新记录一条轻量快照，保留最近 N 条（默认 100），供异常检测与「长时间未使用」判定使用
  - 存储于 `extras`（明文，不含密钥）
  - 历史不足时异常检测**不触发**（宁漏不误报）
  - 上限 N 可配置，避免 extras 无限增长

### 非功能需求

- **NFR1**：不依赖系统语音，跨平台一致
- **NFR2**：网络 TTS 不可用时自动回退到系统语音（可配置）
- **NFR3**：TTS 调用次数可控，避免浪费
- **NFR4**：播报分级 —— 紧急预警不因面板展开而被吞掉；例行播报不打扰正在看面板的用户

### 播报分级规则

| 类别 | 场景 | 收起态 | 展开态 |
|------|------|--------|--------|
| 紧急 | 余额预警 / 用量波动 / 用量耗尽 | 播 | **播** |
| 例行 | 定时兜底 / 长时间未使用 / 异常模式 | 播 | 不播 |

依据：`App.tsx:271` 现有 `if (!ctx.collapsed) return` 是为「例行播报」写的（避免念屏幕上看得到的东西）；但紧急预警的价值恰在用户没盯着时，若沿用该约束则核心功能大面积漏报。

### 约束

- 免费 TTS 服务有每日请求限制（Cloudflare Workers 100,000 次/天）
- 网络延迟 1-8 秒
- 需要处理 DNS 污染问题（国内用户）

## Acceptance Criteria

- [ ] **AC1**：TTS 服务集成完成，能正常播放音频
- [ ] **AC2**：TTS 服务配置界面完成，支持自定义服务
- [ ] **AC3**：未配置 TTS 服务时，播报功能不工作
- [ ] **AC4**：智能播报触发机制工作正常（5 个触发场景）
- [ ] **AC5**：播报间隔可调整（默认 1 小时）
- [ ] **AC6**：网络 TTS 不可用时回退到系统语音（可配置）
- [ ] **AC7**：重复提醒直到确认（点击确认 + 倒计时 1 分钟自动确认）
- [ ] **AC8**：应用级频率限制（每分钟 1 次，每小时 10 次）
- [ ] **AC9**：余额降至阈值时**恰好播报一次**（不重复、不漏报）
- [ ] **AC10**：历史数据不足时异常检测**不误报**（冷启动无播报）
- [ ] **AC11**：TTS 域名无法解析时走系统语音回退（DNS 污染场景）
- [ ] **AC12**：多个场景同时触发时，播报内容合并去重、不逐条念完
- [ ] **AC13**：历史快照数量不超过配置上限（N 默认 100）
- [ ] **AC14**：面板展开时，紧急预警（余额/波动/耗尽）仍能播报
- [ ] **AC15**：面板展开时，例行播报（定时/未使用/异常）不播报

## Design Decisions

| 问题 | 决策 | 说明 |
|------|------|------|
| 设置模块 | 独立「语音提醒」分区 | 在设置页面新增独立分区 |
| 提醒机制 | 重复提醒直到确认 | 触发条件满足时，每隔 N 分钟重复播报，直到用户确认或条件解除 |
| 确认机制 | 点击确认 + 倒计时自动确认 | 用户可点击确认，或等待 1 分钟后自动确认 |
| 阈值配置 | 混合模式 | 全局默认 + 按供应商覆盖 |
| 波动阈值 | 可配置 | 用户可调整波动幅度 |
| 定时兜底 | 可配置 | 用户可选择是否启用定时兜底播报 |
| TTS 不可用 | 可配置 | 用户可选择是否回退到系统语音 |
| 默认播报间隔 | 每 1 小时 | 定时兜底播报的默认间隔 |
| 默认阈值类型 | 两者都支持 | 百分比和绝对金额都支持 |
| 默认阈值数值 | 余额预警 10，用量波动 10 | 默认阈值 |
| TTS 服务配置 | 混合模式 | 预设服务（仅免费）+ 自定义服务 |
| TTS 服务配置界面 | 下拉选择 + 表单 | 用户从下拉列表选择预设服务，或选择"自定义"后填写 |
| 自定义 TTS 配置格式 | URL + 请求格式 + 认证 | 完全自定义满足高级用户需求 |
| 触发场景 | 全部场景（5 个） | 余额预警 + 用量波动 + 用量即将耗尽 + 长时间未使用 + 异常使用模式 |
| 异常使用模式定义 | 可配置 | 用户可选择基于平均值、峰值或标准差，并配置倍数 |
| 视觉通知 | 可配置 | 用户可选择是否显示视觉通知 |
| TTS 频率限制 | 应用级限制 | 每分钟最多 1 次，每小时最多 10 次 |
| 播报内容格式 | 可配置 | 用户可选择简洁或详细模式 |
| 简洁模式 | 仅余额 | 如"余额不足，当前余额 50 元" |
| 详细模式 | 余额 + 用量 + 供应商名 | 如"OpenCode Go 余额不足，当前余额 50 元，使用率 80%" |
| 历史数据 | 轻量采样 | 每次刷新记一条快照，保留最近 N 条（默认 100） |
| 历史不足时 | 不触发异常检测 | 宁漏不误报，避免冷启动期误报 |
| 收起态限制 | 分级放开 | 定时兜底/长时间未使用/异常模式仅收起态播；紧急预警（余额/波动/耗尽）任何状态都播 |
| DNS 处理 | 优雅降级（无内置绕过） | 新域名已实测可直连；应用侧只在失败时回退 + 提示，不内置 DoH/硬编码 IP |
| TTS 端点 | `https://voice.mytts.ccwu.cc/v1/audio/speech` | 实测 HTTP 200 / 1.71s / 有效 MP3；旧 workers.dev 域名被 DNS 污染，弃用 |
| 密钥存储 | 加密 items（非 extras） | 新增专用 IPC，token 不落明文 extras |
