# P1-4 多账户分组管理

## Goal

让多中转站 / 多订阅的用户能把自己的账户按**分组**组织（如「公司 / 个人」），
每组可独立显隐，并能在卡片上区分**同名**的多账号。

竞品依据：CodeZeno（多账户）、CodexBar（多 session）、oh-myusage（账号状态诊断）。
调研原文：`.trellis/tasks/10-01-p1-account-groups/research/`

## Requirements

1. **用户自由标签**：分组不是固定枚举，用户可自建任意组名（「公司」「个人」「中转站A」…）。
2. **筛选 = 只显示选中组**（2026-10-01 用户决策，原为「点组 = 藏它」）：
   选中某一组时**只显示该组**，「全部」显示所有组。被筛掉的账户**仍在后台采集** ——
   与「停用供应商」（`enabled: false`，停止采集）是两件事。
   存储从**黑名单**（隐藏列表）改为**单选**（当前筛选值），语义与读侧随之改变。
3. **托盘与提醒不受影响**：筛选只作用于列表显示 —— 托盘标题与额度提醒**仍覆盖全部账户**。
   设置页必须明示这一点。
4. **同名多账号可区分**：同一预设的两条实例当前**连 logo 都一样**
   （`mark = presetId || protocol`），需要用可辨识的后缀区分（如 `Claude 公司`）。
   没有可区分依据时**不加后缀**（不造「(2)」这类假区分）。
5. **卡片上显示所属组名**（2026-10-01 用户决策）：当前分组只体现在列表聚合上
   （同组卡片聚在一起），卡片本身看不出归属。需要在卡片上加组名标签。
6. **空态不许谎报**（2026-10-01 uitest 发现的真 bug）：
   `ordered.length === 0` 有两个原因 —— **筛选把卡片都筛掉了**（该显示「分组已全部隐藏」
   + 恢复按钮）与**本来就没有卡片可显示**（采集失败 / 快照 id 与实例 id 对不上）。
   后者必须用中性空态，因为「显示全部分组」按钮点了也没用（筛选本来就是「全部」）。
   ⚠ 顺带查出**第三个**原因，而它才是实机三条红的主因：**快照有、注册表里查不到的 id
   被第一版一并滤掉了**（详见 `implement.md` 的 R1）。所以「空态不许谎报」的前提是先
   把「筛掉的」与「查不到的」分开 —— 后者根本不该被筛。
7. **数据诚实**：分组信息只影响展示与组织，不改变任何采集行为与数据口径。
   卡片上的组名标签同理：**查不到实例时不渲染标签**，而不是替用户断言「未分组」。

## Constraints

- **不建组注册表**：分组就是「实例 `groupId` 字段的取值集合」，组名 = 去重结果 +
  一个 `UNGROUPED = '未分组'` 兜底。一份真相源，不存在「组列表与实例列表不一致」的可能。
  删掉一整组 = 把那些实例的 `groupId` 清空。
- **组序不新增持久化维度**：组间顺序 = 该组**第一个成员在数组里的位置**，组内同数组顺序。
  `providers:reorder` 的入参形状（`string[]`）保持不变。
- **只增可选字段**：`ProviderInstance.groupId?` / `ProviderInfo.groupId?` / `distinguishKey?`。
  ⚠ `ProviderSnapshot` **不加**字段（9 个适配器都不该关心它）。
  迁移沿用 `.map()` 归一化先例（照 `encodePetState`）。
- **写入必须「无变化不写」**：`setExtra` 是无条件整文件重写，照抄 `reorderInstances` 的守卫。
- **`ui:hideBalance` 是反面教材，不要抄**：它的 `'1'`/`''` 编码被 spec 自己标注
  「differs from every other boolean — don't copy」。隐藏语义照 `ui:voiceMuted`（id 列表 + 类型守卫）。
- 判「extras 键缺失」只能用 `!v`（`extras:get` 对缺失键返回 `''`，判 `== null` 恒为假）。
- 纯逻辑落 `read-model.ts` —— `scripts/test-read-model.mjs` **已 `loadTs` 它**，
  因此**不新增测试脚本、不改 `package.json`**。

## Acceptance Criteria

- [ ] 筛选某组 → 只显示该组成员，**且这些账户仍在被采集**
- [ ] 「全部」→ 显示所有组；筛选**不重发采集请求**
- [ ] 筛选后**托盘标题不变**（托盘取全局第一位，与 `tray-text.ts` 既有契约一致）
- [ ] 设置页明确写着「筛选只影响列表显示，托盘与提醒仍覆盖全部账户」
- [ ] **卡片上显示所属组名标签**；未分组的显示「未分组」
- [ ] 同名两账号的卡片名带不同后缀；无可区分依据时**不加后缀**
- [ ] `groupNames()` 去重 + 升序 + 含 `UNGROUPED`（当存在无 `groupId` 的实例）
- [ ] `visibleIds()` 按**单个组 id** 返回该组成员；传入 `ALL_GROUPS`（**空串**，不是 `'全部'`）时返回全部
- [ ] `orderForDisplay()` 组间按组首成员位置、组内按数组顺序（**交错数组下**同组成员被聚到一起）
- [ ] **筛到一张卡都不剩（筛选值非空）→ 显示「分组已全部隐藏」空态 + 可用的恢复按钮**
      （⚠ 单选语义下**不存在**「所有组都被藏起来」这个状态 —— 选一个组就一定看得见它。
      这里指的是「选中的那一组一个能显示的卡都没有」，比如该组成员全是未配置。）
- [ ] **本来就没有卡片（筛选值 = 全部 但 `ordered` 也空）→ 显示中性空态，
      不谎称「分组已全部隐藏」，且不显示那个点了没用的恢复按钮**
- [ ] **只筛「注册表里有且被筛选排除」的实例**：快照有、`instanceInfo` 里查不到的 id
      **必须照样显示**（我们不知道它属于哪一组；第一版把它整张滤掉，实机
      `cachedCard` / `cachedBanner` / `localChip` 三条一起红，界面只表现为
      「卡片全没了 + 空态谎称分组被隐藏」）
- [ ] 筛选值持久化在 `ui:groupFilter`；判缺失用 `|| ALL_GROUPS`（**非 `== null`** ——
      `extras:get` 对未写过的键返回 `''`，`== null` 恒为假，这坑本文件踩过两次）
- [ ] 筛选值指向**已不存在的组**时**读侧回落「全部」**且不回写（组随最后一个成员被删而消失）
- [ ] 旧配置迁移：读侧**忽略**已存在的 `ui:groupHidden`（不再使用该键；残留无害）
- [ ] 三个新纯函数**不修改入参**（深比较断言）
- [ ] 三个新函数在 `read-model.ts` 内各只声明一次（静态守卫）
- [ ] 组名写入前截断 32 字符并剥控制字符（会进 SVG / 托盘文案）
- [ ] `--uitest` 断言：分组下拉存在、选项与注册表一致、筛选后卡片变而托盘不变、
      **筛选不重发采集请求**（`lastSync` 不变）、**筛空后的空态 + 一次恢复**、
      **卡片组名标签**、同名后缀、`grpDupCardName` 通过
      （⚠ 分组段**自建夹具**：临时实例无 key → `nodata` → 不占卡片，用来稳定地走到空态）
- [ ] `npm test` 与 `npm run typecheck` 通过
- [ ] **实机 `--uitest` 通过**（`npm run build` 后 `npx electron . --uitest`）
      —— 本批次基线 `158 键 / 131 ok`；第二次 check 实测 **`164 键 / 140 ok / 1 fail`**，
      17 个 `grp*` 键全 ok，唯一 fail 是本机 DPR 已知 flake `petFigureUnchanged`
      （九个字段全等、只有 `canvas` 因 DPR 不同 —— spec 明确要求**不要修**它）。
      ⚠ 实现方报告的 `146 ok` **不可复现**：那 13 条差额是 `vrs` 段（语音提醒）的**假红** ——
      本机 `ui:ttsOn='1'` 让那段的第一条断言前提不成立，随后 12 条跟着崩，与本任务无关；
      另 1 条是 `grpDupCardName`（探针只等 10s，而本机一轮 collect 超过 10s）。两处都已修。
- [ ] 反验实测有效：① 按实例 id 过滤 → 红 8；② 不分组排序 → 红 2；
      ③ 空态判据退回 `ordered.length === 0` → 红 1；④ `hidden` 谓词退回 → 红 1；
      ⑤ 判缺失改 `== null` → 红 2；⑥ 去掉组已消失的回落 → 红 1；⑦ 未知实例谎称「未分组」→ 红 1
      （第二次 check 另复现 12 条，见 `implement.md` 的复核表）

## Notes

- **已知代价（D4）**：组的顺序依赖成员 —— 当某组最后一个成员被移走时，该组位置按剩余成员重算。
  由 I31 钉住。这是不新增「组序」持久化维度换来的。
- **测试夹具陷阱（已处理）**：反验「不分组排序」最初是**绿的** —— 首版夹具用了**连续分组**的数组，
  而连续分组时「纯数组顺序」与「分组后顺序」恰好输出相同。换成**交错数组**
  （`interleaved` / `tri`）后才有红，并加了前置断言 I21 证明数组本身是交错的。
  注释记在该夹具上方，避免下一个人重复这个误判。
- **断言编号在返工时整体重排**（黑名单 → 单选语义，I 段与 J2 段都重写），
  本文提到的 I31 / I21 指的是 `scripts/test-read-model.mjs` 里的**当前**编号。
- 设计推导见 `design.md` 的 D1–D6，执行清单见 `implement.md`。
