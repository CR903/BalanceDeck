# Tauri 迁移评估（纯调研）

## Goal

评估从 Electron 迁移到 Tauri（Rust 后端 + Web 前端）的成本与收益，输出一份**可直接据此决策**的
分析文档：读者读完能回答「迁 / 不迁」，而不是「各有优劣」。

**本任务只产出文档，不改产品代码。**

## Requirements

### R1 评估范围（四条主线，缺一不可）

| # | 主线 | 必须回答的问题 | 支撑材料 |
|---|---|---|---|
| **R1** | **能力对等** | 本项目用到的 Electron 能力，Tauri 2.x 有没有对等物？逐项对照，**没有就明说没有**，并给出官方 issue 状态 | [`research/01-capability-parity.md`](./research/01-capability-parity.md) |
| **R2** | **成本** | 迁移要多少工作量？按块拆（A 后端 / B 前端 / C 测试 / D 构建分发），每块给理由，最后给**区间**而不是单点 | [`research/02-cost-estimate.md`](./research/02-cost-estimate.md) |
| **R3** | **收益** | 迁完能省什么？体积 / 内存 / 启动分别多少，**哪些是本机实测、哪些是外推** | [`research/03-benefit-metrics.md`](./research/03-benefit-metrics.md) |
| **R4** | **竞品对照** | 有没有别人真的迁过？结果如何？**找不到先例也要作为结论写出来**，不能当作「没查到就跳过」 | [`research/04-competitors.md`](./research/04-competitors.md) |

R1–R4 全部以**本仓代码实读**为底（能力清单逐项带 `file:line`），不靠框架文档的通用对比表。

### R2 结论要求

- 结论必须是**单选**（迁 / 不迁 / 有条件），并落到本项目的具体事实上，不写「建议进一步评估」。
- 若结论是「不迁移」，必须同时给出**「不迁移的前提下现在该做什么」**的可执行清单。
- 成本、收益、风险三条线**分列**，不混在一个「综合来看」里。

### R3 证据纪律

- **实测**与**外推**必须逐项标注，不把外推当实测。无法在本机验证的一律写「未验证」。
- 引用的官方 issue / 文档要有出处与检索日期。
- 找不到证据时**如实写「没找到」**（这是信息，不是失败）。

### R4 边界（不做什么）

本任务**明确不做**以下任何一项：

- ❌ **不写任何产品代码**，不改 `src/`、`scripts/`、构建配置、依赖。
- ❌ 不打迁移分支、不做 PoC 迁移、不引入 Rust / Tauri 依赖。
- ❌ 不做 Tauri spike（那是被建议的下一步，不在本任务内，见 R2 的清单第 2 条）。
- ✅ 只允许新增 / 修改 `.trellis/tasks/10-01-tauri-eval/` 下的文档。

## Acceptance Criteria

> 验收对象是**调研交付物的质量**，不是代码。以下逐条对应 [`verdict.md`](./verdict.md)。

### 关于结论

- [x] **AC1 结论明确到可决策**：TL;DR 给出单选结论（**建议：不迁移，维持 Electron**），
      不是「各有优劣 / 需进一步评估」。
- [x] **AC2 结论落到本项目事实**：6 条理由逐条引用本仓具体事实
      （221 MB 素材、`--uitest` 2,500 行 / 259 处 `executeJavaScript`、
      `safeStorage`、tauri#14263、10,573 行主进程、无 CI / 无 updater / 未签名）。
- [x] **AC3 给了「不迁移的前提下现在该做什么」**：§五 4 条可执行清单
      （先量素材 / 1 人日 spike / 补 CI / 跟踪两个 blocker），每条带判定标准。

### 关于成本

- [x] **AC4 成本有区间而非单点**：合计 **116 人日（现实区间 116–156）**，分 A/B/C/D 四块，
      每块给理由与行数依据。
- [x] **AC5 成本做了人日折算**：116 人日 ≈ 23 周 ≈ 5.7 个月单人；156 人日 ≈ 31 周 ≈ 7.8 个月单人。
- [x] **AC6 点出了最易被低估的三项**（`--uitest` 12–15 / 适配器 22 / 密钥存储 5），
      并另计 Rust ramp-up 5–8 人日。

### 关于收益

- [x] **AC7 区分「实测」与「外推」**：收益表有独立的「确定性」列 ——
      体积标 **高（结构必然）**、内存标 **低（外推，需 1 人日 spike）**、启动标「高但用户感知低」。
- [x] **AC8 实测项给了本机基线口径**：385.5 MB 常驻（按进程分 Physical footprint，
      非 RSS，并说明为何不用 RSS）、冷启动 3 次实测。
- [x] **AC9 未验证项没有被写成结论**：压缩后 dmg 体积明确标「远小于 53%，未验证」；
      §六 另列 9 项待验证 + 验证方法 + 阻断性。

### 关于能力缺口

- [x] **AC10 阻断级能力缺口单独成表**：4 项（`safeStorage` 无官方对等 /
      OAuth 弹窗 / 穿透 + `forward:true` / autoplay 开关），每项带本项目用法 `file:line`。
- [x] **AC11 阻断项带官方 issue 状态**：`tauri#14263` **open**、
      Stronghold **已宣布 v3 移除**、穿透 **官方明确不会实现（#13070）**、
      拖拽 #11605/#10767、托盘已知 bug #13415/#8255。
- [x] **AC12 缺口不是「换个 API」的轻描淡写**：37 项能力逐项分「对等 / 有条件 / 阻塞」三级，
      并指出 11 项重点核实项里**没有一个是干净映射**。

### 关于证据与边界

- [x] **AC13 竞品对照给了可信度分级**（⭐ 一手 / 二手 / 有利益相关），
      并把 **Fluxzy「业务逻辑在 main 是难模式」**与本项目对上。
- [x] **AC14 证据空白作为结论写出**：菜单栏/托盘类应用的迁移复盘 **找不到**、
      3D/WebGL 重应用迁移案例 **找不到**、Wails 对照未有效检索到 —— 并判定
      「找不到同类型成功先例，本身就是一个信号」。
- [x] **AC15 事实修正留痕**：调研中修正任务清单的 3 处错误说法（`qa/` 路径、
      `globalShortcut` 全仓 0 处使用、对兄弟任务内存基线的依赖）。

### 关于交付物自身

- [x] **AC16 正式交付物在任务根目录**：`verdict.md`；5 份取证材料在 `research/`，
      报告内相对链接逐个核对可解析。
- [x] **AC17 交付文档不是过期快照**：§八「后续执行结果」记录 2026-10-01 兄弟任务
      `10-01-p1-5-resource` 已把头条论据执行完 —— 核心推论**由推论升级为实测**
      （素材占比 87 % → 实测 90.5 %），§五 清单已标注完成状态
      （1 条完成 / 3 条待办），并**勘误**了 §三 的基线口径（478 MB 是求和值，
      `.app` 实测 520 MB）。
- [x] **AC18 未实测项被明确隔离**：优化后 `.app` 整包体积**未实测**
      （`electron-builder --dir` 两次 600 s 网络超时），**推算值不得进入任何结论性表述**；
      Tauri 侧内存收益**仍是外推**，本轮只有 Electron 侧数字。
- [x] **AC19 「不迁移」结论经复核仍成立**：三条理由逐条核对，
      `safeStorage` / `tauri#14263` / `--uitest` 耦合度量（实测仍 2,505 行 / 259 处 `exec()`）
      均未被资源优化触及；`src/main/` 下除 `qa/uitest.ts` 外零改动
      → A 块 70 人日成本估算原封有效。

## Out of Scope
