# 球形态：去掉浅色皮肤下的背景框 + 5H 移到数字下方 + 自动轮播先走完窗口

> 任务 `09-28-dot-frame-label-carousel`，P1。上一任务 `09-27-dot-ring-scroll` 的用户实测反馈。

## 一、需求

### R1 球不得借用页面级表面令牌（背景框）

`.petball-fallback` 用 `background: var(--bg)` 当底盘。`--bg` 是**主界面卡片/页面的表面色**，
与「桌面壁纸长什么样」毫无关系，于是球的外观被皮肤绑架。

**实拍取证**（`BD_SKINS=1 npx electron . --ballshot`，`/tmp/balancedeck-shots/ball-skin-*.png`）：

| 皮肤 | `--bg` | 球盘实测 |
|---|---|---|
| `aero`（浅色） | `rgba(246,246,248,0.72)` | 浅灰盘 |
| `minimal` 极简白 | `#ffffff` | **纯白盘** |
| `candy` 渐变彩 | 粉蓝渐变 | 浅色盘 |
| `ink` 墨纸 | `#f4f1ea` | **米色盘**（白底桌面上非常明显） |
| `dark` 深色科技 | `#101014` | 黑盘 ✓ |

6 个皮肤变体里 **4 个给浅色盘**。而 `dark` 之所以「看起来没问题」纯粹因为它碰巧和深球同色 ——
不是设计，是巧合。

**关键取证（推翻了「球应当恒定」的直觉）**：`--track` 是**逐皮肤对着该皮肤的球盘调**的 ——
`minimal` 用 `rgba(0,0,0,0.08)`（深色轨道，配浅盘），`dark` 用 `rgba(235,235,245,0.14)`
（浅色轨道，配深盘）。**球的底色跟随皮肤是现有令牌体系的自洽设计**，不是缺陷；
`--track`/`--dot-rim`/`--dot-bottom` 三个令牌 5 个皮肤全都定义了，唯独**缺一个表面色**，
球才去借了页面级的 `--bg`。

**要求（2026-09-28 用户拍板：逐皮肤补球表面令牌）**：新增球专属的表面令牌（如 `--ball-bg`），
逐皮肤取值，**不再借 `--bg`**；`minimal`/`ink` 这类浅盘要把 rim/track 的对比加强，
让球在白底桌面上读作「一个物体」而不是「一块底色」。尊重皮肤作者的配色意图，
**不改「球随皮肤变色」这件事本身**。外部皮肤（`ext:*`）未定义时要有兜底，不许塌成透明球。

### R2 去掉 `backdrop-filter`（**保留，但病根另有其人 —— 2026-09-28 实机复测后订正**）

`.petball-fallback` 曾写着 `backdrop-filter: blur(24px) saturate(180%)`，注释意图是「磨砂桌面背景」。
但**悬浮窗是 `transparent: true`（`src/main/overlay.ts:138`），页面内 `html/body/#root` 全部
`background: transparent` —— 页面里不存在任何可被采样的 backdrop**，它履行不了注释宣称的职责。
**这一条删除成立，予以保留。**

⚠️ **但它不是用户报的那个「球外面套一圈浅色方框」的成因** —— 删掉后方框仍在（用户实机复测）。
本条原先把方框归因于此，是**错误诊断**，已订正（见 R5）。

**教训（写进 spec 的候选）**：`capturePage` 拍不到屏幕合成结果，因此**「实拍没变化」不能当作
「改对了」的证据**。同一个症状被解释过一次、又被证伪一次，根因是拿一个**当前工具看不见的层**
（原生窗口合成）去解释现象。

### R5 方框的真正成因：原生窗口层（2026-09-28 实机定位）

**用户两个实机观察（决定性）**：

1. 把球拖到桌面别处 → **方框跟着走** ⇒ 它属于我们的窗口，不是桌面上别的窗口
2. 拖到深色背景上 → **方框仍是同样的浅灰，不随背景变** ⇒ **不是半透明透出桌面**，
   是窗口**自带的不透明浅色底**

**已逐项排除**（全部为静态取证，非推测）：

| 候选 | 排除依据 |
|---|---|
| 页面 CSS 画了方框 | `--ballshot` 的 `capturePage` 出透明 PNG、不含桌面合成却**拍不到方框**；页面若有底色必然被拍到。且 `.petball*` 中唯一满幅背景就是 56×56 的圆本身，`.petball-stage`/`.petball-hit` 无背景 |
| 窗口阴影 | 收起态 `hasShadow` 由 `setCollapsed` 动态置 `false`（`overlay.ts:288`） |
| 原生 vibrancy | 代码中已无（`overlay.ts:135` 记录了移除历史） |
| `.petball-debugring` | QA 专用粉色虚线，仅 `debugRing` 时渲染 |
| 半透明透出桌面 | 用户观察 2 直接排除 |

**剩下的唯一层级 = macOS 原生窗口层**。窗口 56×56、页面透明，却仍有一块不透明浅色圆角矩形，
符合 Electron ≥30 在 macOS 上**默认 `roundedCorners: true`**、以及
`transparent` + 原生窗口底色 interplay 的已知问题类（Electron 37.10.3）。

**要求**：显式关掉原生圆角并把窗口底色**在创建后再设一次**（`transparent` 在 macOS 上
不总是一次生效），让 56×56 窗口的四个角与内部都真正透明；球本身的立体感由
`.petball-fallback` 的 inset 阴影负责，**不依赖任何原生效果**（用户口径：「可以做立体效果就行」）。

**取证限制（必须如实记录）**：本机 `screencapture` **没有 Screen Recording 权限**，
只输出桌面图片、**略过所有窗口**（两次抓屏均只得到壁纸），因此**原生层的视觉结果无法由
AI 侧自行取证**，只能由用户实机确认。这是本条唯一的人工门。

### R3 短标签移到百分比正下方 + 更小 + 换字体

现状：`left:0; bottom:0` 塞在左下角，9px，与环外缘只剩 **1.3px 余量**（当时 design 算出来的，
还留了「压环就退 8px」的预案）。用户要求：

- 位置：**百分比数字正下方**（球内居中，数字与标签同一列）
- 字号：更小
- 字体：换成一个**明显不同**的字体观感

移到正下方顺带解掉 1.3px 死结：盘内可用直径 49px，`13px 数字 + 9px 标签 ≈ 24px`，从容。

**字体只有一处 stack**（`skins.css:198`，`-apple-system` 系 sans），全项目**没有第二种字体观感**，
所以「换字体」必须**新引入一个 stack**。推荐等宽（`ui-monospace, SFMono-Regular, Menlo, monospace`）：
8–9px 下等宽的数字/字母辨识度与「技术读数」语义都比系统无衬线更像一个仪表标签。

### R4 自动轮播先走完窗口再换供应商

现状（`PetBall.tsx:331-338`）：自动 tick 每 6 秒调 `advanceProvider(1)`，而
`advanceProvider` 内部固定 `setWinIdx(0)`；`stepWindow` **只被滚轮调用**。
所以**自动轮播只换供应商、且永远停在 `windows[0]`（5H）** —— 用户看到的
「快速切供应商但从不切时限」是当前代码的字面行为。

> 注：上一任务的原话「上下滚动切换 5H、周、月」被实现成了**纯手动**，自动那层压根没接。
> 这是本任务补的洞，不是回归。

**要求**：自动轮播在**同一家内**按窗口顺序逐个走完（5H → 周 → 月），走完才换下一家。

## 二、验收

### R1 / R2 背景框
- AC1.1 球盘底色由**球自己的令牌**决定：`.petball-fallback` 的**生效声明**里是 `var(--ball-bg)`，
  且不引用 `--bg`。
  ⚠ 判据必须**剥注释后按选择器配平花括号取整块**（2026-09-28 check 修正）：原文写的
  `grep -A14` 够不到 `background`（它在选择器下方第 18 行），且 `grep petball-fallback` 的
  首个命中是 `:root` 里的一条注释 —— 照字面执行会写成一条**永真的假护栏**。
  由 `scripts/test-structure.mjs` 的 D1 执行。
- AC1.2 5 个内置皮肤逐个实拍（`BD_SKINS=1 npx electron . --ballshot`）：`--ball-bg` **5 个皮肤都有定义**，
  且每个值的**对比度**足以让盘与桌面分开（`minimal`/`ink` 重点验）
- AC1.3 `.petball-fallback` 的**生效声明**里没有 `backdrop-filter` / `-webkit-backdrop-filter`。
  ⚠ 判据必须**剥注释**（2026-09-28 check 修正）：该块内有一条注释解释「这里原来有
  backdrop-filter、为什么删」——它是本任务最有价值的一条知识，不能为了让字面 grep 归零而删掉。
  照原文的「块内 grep 0 命中」执行，这条 AC **永远为假**。由 D2 执行。
- AC1.4 **真实桌面人工复现（AI 侧无法取证）**：把球放到纯白背景上，确认那圈浅色圆角框**消失**（不是「变淡」）。
  ⚠️ 本机 `screencapture` 无 Screen Recording 权限（只输出桌面、略过窗口），
  `--ballshot` 的 `capturePage` 也不含桌面合成 —— **AI 侧拿不到这个证据**，必须由用户确认
- AC5.1 `BrowserWindow` 显式 `roundedCorners: false`，且创建后**再调一次** `setBackgroundColor('#00000000')`
- AC5.2 球在纯白桌面与纯黑桌面上都**只呈现圆形**，四角无任何方形底
- AC5.3 球的立体感（顶部高光 / 盘缘 / 底部内阴影）**由 CSS inset 阴影提供**，
  不依赖原生窗口阴影或任何原生材质
- AC1.5 外部皮肤（`ext:*`）无该令牌定义时**不塌陷**（有 `:root` 兜底），不出现透明球

### R3 标签
- AC3.1 标签渲染在百分比**正下方居中**，多窗口时显示、单窗口仍不显示（沿用上一任务口径）
- AC3.2 **只管标签**：标签不压环（环笔画内缘 r=19.5 以内）、不压数字（紧邻其下、间隙 ≤5px）、不溢出 56×56。
  ⚠ **数字的既有内探不在本任务范围**（2026-09-28 check 裁决）：4 字值（`37.1%`）的数字墨迹
  最大半径 20.6px > 环笔画内缘 19.5px，探入 1.1px。这是 4 字值比 3 字值宽的**既有事实**，
  旧角落布局下余量更小（≈0.3px），轨道与盘面亮度只差 ~20 级、无视觉碰撞；
  数字的字号/字距是上一任务的既有设计，不在本任务改动范围，因此**不为此加 `padding-top`**
  —— 那会把整组推离几何计算值。若将来要收数字内探，另立任务。
- AC3.3 标签字体与 `--dot-value` **不是同一个 stack**（`grep` 可验），且为 8–9px
- AC3.4 标签取值仍来自 `shortWindowLabel()`，随窗口切换同步变化

### R4 自动轮播
- AC4.1 一个有 3 个窗口的供应商：自动轮播**先**依次显示 3 个窗口，**之后**才换供应商
- AC4.2 单窗口供应商：自动轮播直接换人（不空转一步）
- AC4.3 手动操作后仍**暂停 8 秒**，第 9 秒起恢复（沿用上一任务 AC4.3）
- AC4.4 手动左右切供应商后落 `windows[0]`，随后的自动轮播从那里**继续往后**走（不跳回 5H 之外的地方）
- AC4.5 人物形态零影响（上一任务 8 个确定性字段逐位不变）
- AC4.6 充值余额供应商（无环）同样遵守「先走完窗口再换人」

## 三、约束

- 不引入新依赖、不新增设置项、不新增持久化键
- **不新增 WebGL 上下文**（球形态保持 2D）
- 上一任务的四条设计红线继续有效，其中红线「换人唯一入口」需按 R4 微调（见 `design.md`）
- `--uitest` 必须带 `BD_USER_DATA=<临时目录>`；`npx electron . --X` 跑的是 `out/`，
  **任何源码改动后先 `npm run build`**（`quality-guidelines.md` 已有该契约）
- 磁盘仅剩 ~4GB，`--uitest` 偶发挂起是已知退出 flake

## 四、范围外

- 人物形态（`BD_PET=1`）的任何视觉改动
- 轮播节奏（6 秒）与暂停时长（8 秒）的调整
- 外部皮肤作者文档（只保证不塌陷，不为外部皮肤定调色板）
- 主界面卡片里是否也该有同样的表面令牌（另立）
