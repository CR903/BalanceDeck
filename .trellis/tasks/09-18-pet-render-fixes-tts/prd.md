# 宠物渲染修复与定时播报

覆盖用户 2026-09-18 反馈的 4 项：人物渲染发黑、悬浮球贴边被裁成半圆、走动没有纵深缩放、
余额/用量没有定时播报。第 5 项「人物真人化」拆到兄弟任务 `09-18-human-realism`。

## Goal

让 Aria/Ray 以正常肤色站在球里走动、走到边缘自然停下而不是被窗口切成半圆、走近明显变大走远变小，
并按设定间隔用系统语音播报当前焦点供应商的余额与用量。用户价值：桌宠从"黑剪影 + 被裁切"变成可看的陪伴物。

## Background（已实测确认的事实，非推测）

- **发黑根因**：`/tmp/probe-fbx.mjs` 解析 `resources/human-pets/aria/model.fbx` 与 `ray/model.fbx` 得到
  3 个 `MeshPhongMaterial`，**`color` 全为 `000000`**，`map`/`normalMap` 均存在。three 的漫反射是
  `material.color × map.rgb`，黑 × 贴图 = 纯黑，所以打光怎么调都是黑剪影。
  Rocketbox 是给 Unity/Unreal 做的，`DiffuseColor` factor 留黑、albedo 全靠贴图，`FBXLoader` 忠实写进了 `color`。
  基线截图：`/tmp/balancedeck-shots/pet-aria.png`、`pet-ray.png`（纯黑人形）。
- **IBL 结构性失效**：`WebGLRenderer.js:2050` 只把 `scene.environment` 交给 `MeshStandardMaterial`；
  Phong 材质没有 `envMapIntensity` 属性（实测 `ABSENT`），因此 `human.ts:139-140` 是静默空操作，
  `scene.ts:147-155` 的 `RoomEnvironment`（DESIGN.md:277 称其为"PBR 质感的关键"）从未作用到真人模型。
- **半圆裁切根因**：漫游区是硬编码世界常量 `walker.ts:50` `halfX:58`，`PetBall.tsx:149` 调用
  `createPet3dScene(host, id, { roam })` 从不覆盖它。按 `scene.ts:31-35,142-144` 常量反算
  （相机 (0,63.5,162) → 球心距 165.5，FOV 35°，宠物形态窗口 320×230 → 可见半宽 ≈72.6 世界单位），
  球要完整可见需 `|x| ≤ 72.6 − 28 = 44.6`；`58 > 44.6` → 约 48% 球径悬在窗口外，被透明窗口切掉。
- **纵深**：`walker.ts` 已有 z 轴、`scene.ts:559-561` 已把 x/z 写进世界坐标、相机是真 `PerspectiveCamera`
  → 透视缩放本来就会自动发生，**不需要手工缩放**；问题是 `halfZ:13` 太浅（±13 只有 0.92×–1.08×）看不出来。
- **转身**：`walker.ts:27-28,126` 算了 `facing`，但 `scene.ts:593-627` 从未读取（死值）；
  `walker.ts:9-11` 记录了"始终面向镜头"的原始取舍，本任务只对真人系改这个取舍。
- **播报**：`src/` 全量 grep `speechSynthesis|tts` → **0 命中**，现在只有 `PetBall.tsx:336-345`
  的 90s **一次性** `setTimeout` 文字泡泡（随数据变化重建，不是周期定时器）。
- **贴图 404**：FBX 引用 `f014_body_specular.tga` / `f014_head_specular.tga`，而
  `scripts/fetch-human-pets.mjs:73` 刻意排除 specular → 运行时每个材质发一次注定失败的请求。
  color/normal/opacity 的 PNG 实测齐全且与 `human.ts:43` 的重定向路径对得上（不是发黑原因）。

## 步骤 2 实测修正（2026-09-18，CP2 通过）

- 320×230 下反算结果 `halfX = 34.13`、`halfZ = 13`（不是 PRD 初稿估的 44.6）。
  初稿低估的原因：用了 `r = 28`（实际轮廓半径 28.96）、忽略球在 `z = +halfZ` 侧离镜头更近导致投影变大、
  且把球轮廓按正圆处理（贴边时真实轮廓是横椭圆，实测宽约 4.7%），故 `margin` 必须 ≈4 而非 0。
- 判据实测：aria ink box `{79,51,133,132}`、ray `{164,51,142,133}`、mochi `{127,50,131,131}`，
  全部完整落在 320×230 内；把宠物钉在最坏角 `(34,13)` 时右缘 316（独立探针预测 316.2）。
- **纵深与横向互斥**：同一相机下若把 `depthBudget` 给到 34，`halfX` 会塌到约 19.5。
  要"走近明显变大且不裁切"，必须动相机几何或动"球跟人走"这条既有行为，**放大窗口无效**。
| D5 | 材质修复边界（本任务 vs 真人化） | 本任务只做「Phong→Standard + 反照率修正」这一最小正确修复；皮肤/毛发/眼睛/重打光属真人化 |

## Requirements

### 渲染正确性

- **R1**：真人模型不再输出纯黑。FBX 材质加载后转为 `MeshStandardMaterial`，携带原 `map`/`normalMap`/`alphaMap`
  与透明标记；当 FBX 的 Diffuse factor 为黑（`color ≈ 0`）时反照率修正为白，让贴图决定颜色。
- **R2**：`scene.environment` 真正作用到真人模型（R1 的转换是前提）；删除 `human.ts:139-140` 的空操作，
  改为在转换后的材质上显式设 `envMapIntensity`。
- **R3**：（2026-09-18 CP1 修正）FBX 引用的 specular 贴图不在仓库里，`LoadingManager` 重定向后必然 404。
  原写法「加载后丢弃 `specularMap` 消除 404」**不成立**：404 发生在 FBXLoader 解析期（早于材质对象存在），
  且 `MeshStandardMaterial` 根本没有 `specularMap` 属性。实际处置 = 转换时**不搬迁**该属性（已做），
  404 本身降级为**非目标**（要消得在 `managerFor` 层按已采集清单拦截，属噪音治理，见 Out of scope）。
- **R4**：Q 版 8 只（无骨骼 GLB）的渲染结果与观感不得改变。

### 边界与纵深

- **R5**：漫游区半宽/半深**由视口反算**，不再用硬编码常量：以「球壳与用量环的轮廓完整落在窗口内」为约束，
  在 `resize()`（含窗口尺寸变化、形态切换）时重算并写回 `WalkerConfig.area`。
- **R6**：走到边缘时**停住**（宠物中心被夹在可行区内），不得出现被窗口裁成半圆的帧。
- **R7**：（2026-09-18 改写，原「窗口 320×230 → 460×340」前提已被实测推翻）**球壳与用量环只跟随宠物的 x，
  不再跟随 z**（去掉 `scene.ts:561` 的 z 跟随），窗口保持 `320×230`。这样球恒定在窗口内不裁切，
  宠物的纵深不再受"球必须在任意 z 都完整可见"的约束。
- **R8**：DOM 覆盖层（caption / 余额泡泡 / 角标 / 过期提示）随行为变化重新核对，
  在任何可行位置都不得越界（`skins.css:1463` 的 `overflow: hidden` 是共犯，需一并处理）。
- **R9**：`halfZ` 从 13 提到 ~28，**走近明显变大、转身走远明显变小**（透视自然产生，
  禁止在归一化层加手工缩放——`scene.ts:416-418` / `DESIGN.md:312-314` 记录过该回归）。
  目标缩放跨度 ≥1.35×（现状 1.17× 用户反馈"看不出来"）。
  宠物走到球外前方时**允许**视觉上离开玻璃球壳（D4' 的既定取舍），但不得走出窗口。
- **R10**：真人系朝向改为**跟随行进方向偏航**（走向镜头时看到正面、走远时看到背面），带平滑过渡；
  Q 版保持现有「只左右翻转、始终面向镜头」的取舍不变。
- **R11**：拖拽路径的窗口夹取（`overlay.ts:307-308` 允许约 40px 出屏）与其他路径
  （`overlay.ts:231-233` 严格夹在 workArea）口径统一，避免拖到边缘后球被屏幕切。

### 定时语音播报

- **R12**：新增系统语音播报：按设定间隔用 `window.speechSynthesis` 播报**当前焦点供应商**的余额与用量百分比，
  中文语音优先，取不到中文音色时回退系统默认音色。
- **R13**：设置页「宠物」分区新增开关（默认**关**）与间隔选择（默认 60 分钟，档位 15/30/60/120），
  持久化沿用 `ui:*` extras 键位模式（`App.tsx:210`）。
- **R14**：隐私与数据诚实口径复用现有规则：`hideBalance` 开启时**不播报金额**（百分比不受影响，与卡片一致）；
  缓存/估算数据沿用现有「（缓存）/（估算）」措辞；状态为 `failed`/无数据时不播报。
- **R15**：定时器必须是**单个自重排定时器**并在卸载/设置变更时清理，不得叠加
  （`scheduler.ts:94-97` 记录过 runaway-timer 事故）；展开面板与拖拽期间不触发播报。
- **R16**：现有 90s 一次性余额泡泡行为不回退（R12 是叠加能力，不是替换）。

### 质量

- **R17**：无回归——`npm run test:walker`、`npm run test:pet`、`npm run typecheck`、宠物相关 uitest 全绿；
  `walker.ts` 新增的视口反算要有单测覆盖（给定窗口尺寸/相机参数 → 期望 halfX/halfZ）。

## Constraints

- 素材不得进仓库：`resources/` 已在 `.gitignore:13`，走 `bd-asset://` 与 `extraResources`。
- 不改 `renderer` 的透明窗口/点击穿透机制（`overlay.ts:341-408`），只改尺寸与夹取口径。
- 不引入新依赖（`speechSynthesis` 是 Web 标准，macOS 自带音色）。
- 已知平台限制（本任务不处理，仅记录）：`fetch-human-pets.mjs:80` 用 macOS 专有 `sips`，`predist:win` 无法产出 PNG。
