# 语音设置重构与播报故障修复

## Goal

删掉「语音播报音色」这个反直觉的设置项（TTS 音色与系统语音性别各走各的逻辑），并修掉测试播报完全失效、不可达状态粘滞、错误提示不友好三个问题。

## Background

### 已定位的三个缺陷（均实测确认，非推断）

服务本身正常：`POST https://voice.mytts.ccwu.cc/v1/audio/speech` → HTTP 200 / 1.39s / 13104B 有效 MP3。问题全在应用侧。

**缺陷 1 · 测试播报被频率闸门静默吞掉**

`speechOut.ts:242` 的 `if (!allowCall(Date.now())) return` 位于所有播报的公共路径上。闸门是 1 次/分钟、10 次/小时，因此第二次点击「测试播报」被**静默丢弃** —— 无日志、无提示、无声音。

设计错误：频率闸门是为限制**定时播报**消耗免费配额而设，不该限制**用户主动点击**。上一轮把测试按钮接进统一播出口时连闸门一起继承了。

**缺陷 2 · 「服务当前不可达」是粘滞假警报**

`onTtsOk`（清除标志）只在 TTS 成功播完后触发。因缺陷 1，后续所有播报都被闸门拦下 → 永远没有成功 → `unreachable` 永久为真。

即两个症状是**同一根因的因果链**：某次失败置位 → 闸门挡住修复 → 用户看到的正是「提示不可达 + 点了没反应」。

**缺陷 3 · 提示文案面向实现而非用户**

现文案：「上一次调用语音服务失败，**服务当前不可达**。播报会按下面的设置**回退到系统语音**；换端点或稍后点「测试播报」验证连通性。」

用户不知道「回退到系统语音」意味着什么（= 用 macOS/Windows 自带音色念，效果不同但仍会响），也不知道现在该做什么。

### 设计冗余：性别设置项

`ui:voiceGender` 存在，但用户要回答的问题是「Aria 还是 Ray 播报」，而性别下拉要用户对着技术概念选「女声/男声」。TTS 走 `voice`（21 个音色）配置、系统语音走性别关键词匹配，两条路各有一套设置。

集成复核时 `changePet` 静默改写 `ui:voiceGender` 曾被判为「越界、覆盖用户显式偏好」而还原 —— 那是因为下拉还在，用户有显式选择。现在下拉要删，该顾虑消失。

## Requirements

### 功能需求

- **FR1**：设置页删除「语音播报音色」下拉
- **FR2**：TTS 预设提供**音色选择**（21 个，含性别与性格标注）与**语音风格**（11 个）
- **FR3**：系统语音性别**完全由所选数字助理决定** —— Aria→女声，Ray→男声；设置页不再有性别开关
- **FR4**：切换助理即时生效（不必重启、不必改设置）
- **FR5**：「测试播报」**不受定时播报频率闸门限制**，可连续点击
- **FR6**：不可达状态**不得粘滞** —— 能恢复则自动恢复，恢复不了则给出可操作指引
- **FR7**：错误提示改为口语化，说明「发生了什么 + 现在该怎么办」
- **FR8**：`ui:voiceGender` 下线，读取旧值仅用于一次性迁移

### 非功能需求

- **NFR1**：不引入新依赖
- **NFR2**：旧配置升级后不崩、不静默失效
- **NFR3**：频率闸门仍然约束定时播报（配额保护不能因此削弱）
- **NFR4**：测试须覆盖三个缺陷的复发

### 约束

- 频率闸门的存在理由是保护免费服务配额（10 次/小时），不可整体移除
- 21 音色 / 11 风格取自 `https://voice.mytts.ccwu.cc` 的实际清单，不臆造
- `voiceGender()` 的性别关键词判断曾误判（Yu-shu 实为女声），新增音色映射不得重蹈

## Acceptance Criteria

- [ ] **AC1**：设置页无「语音播报音色」下拉
- [ ] **AC2**：可选 21 个 TTS 音色与 11 个语音风格，且**两者都被真正发送**到 API
- [ ] **AC3**：选 Ray → 系统语音回退为男声；选 Aria → 女声；无需任何额外设置
- [ ] **AC4**：切换助理后立即影响下一次系统语音播报
- [ ] **AC5**：1 分钟内连续点击「测试播报」3 次，**3 次都能发出声音**
- [ ] **AC6**：定时播报仍受 1 次/分钟、10 次/小时限制（配额保护未被削弱）
- [ ] **AC7**：一次失败后，若服务恢复，「不可达」提示能自动消失
- [ ] **AC8**：错误提示不含「回退到系统语音」这类实现术语，且明确给出下一步
- [ ] **AC9**：从 `ui:voiceGender` 升级的老用户播报功能正常
- [ ] **AC10**：三个缺陷各有一条能在其复发时变红的断言

## Design Decisions

| 问题 | 决策 | 说明 |
|---|---|---|
| 性别来源 | 完全由助理决定，无手开关 | 用户裁定 |
| 测试播报 vs 频率闸门 | 测试播报**绕过**闸门 | 闸门保护的是定时配额，不是用户主动操作 |
| 不可达自愈 | 定时重试探测 + 成功即清除 | 不能只靠下一次播报碰运气 |
| 错误文案 | 「发生了什么 + 你可以做什么」 | 禁实现术语 |
| 音色数据 | 取自服务页面实际清单 | 不臆造 |

## Out of Scope

- 新增 TTS 服务商（仍只有免费 + 自定义）
- 流式 TTS
- 多语言播报
- 音调（pitch）暴露为设置项（服务支持，但本次不暴露）

## Notes

- 参考清单已抓取：21 音色（晓晓/云希/云扬/晓伊/云健/晓辰/晓涵/晓梦/晓墨/晓秋/晓睿/晓双/晓萱/晓颜/晓悠/晓甄 + 云枫/云皓/云夏/云野/云泽）、11 风格（通用/智能助手/聊天/客服/新闻播报/亲切温暖/平静舒缓/愉快欢乐/温和柔美/抒情诗意/严肃正式）
- 缺陷 1 与 2 的耦合关系是本任务的核心洞察：只修其一不能解决用户看到的现象
